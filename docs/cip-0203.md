# Dingo block producer version payload

Dingo uses scheme 0 and implementation identifier 69 in the block header's
minor protocol version (the self-reported software tag in Dijkstra).
By default, the payload is zero and the header value remains 69.

Enable version disclosure with `--cip-0203-enabled`, YAML
`cip0203Enabled: true`, or `DINGO_CIP0203_ENABLED=true`. The Go node option is
`WithCIP0203(true)`. CLI settings override environment settings, which override
YAML. This controls forged headers, including dev-mode headers; it does not
change ledger protocol parameters, era selection, or peer handshakes.

The version comes from the same linker-populated `internal/version.Version`
used by `dingo version`. No runtime version override is provided. A build with
this option enabled must have a semantic release version (an optional `v`
prefix is accepted). Missing, malformed, or out-of-range versions are errors.
Development builds can set `VERSION` when building with the Makefile.

## Payload specification

The 22-bit payload contains unsigned release components:

| Payload bits | Width | Component | Range |
| --- | --- | --- | --- |
| 21–16 | 6 | Major | 0–63 |
| 15–8 | 8 | Minor | 0–255 |
| 7–0 | 8 | Patch | 0–255 |

```text
payload = (major << 16) | (minor << 8) | patch
header_minor = (payload << 8) | 69
```

Scheme bits 31–30 remain zero. Prerelease and build metadata are omitted:
`v1.2.3-rc.1` and `v1.2.3` both encode as `0x01020345` (16909125).
The payload does not identify a commit or distinguish prerelease builds.
Zero payload also covers the historical identifier-only value 69, so it must
not be interpreted as proof of release 0.0.0. Other nonzero payloads retain
this interpretation permanently.

Consumers first check the scheme and identifier, then decode
`major = (payload >> 16) & 63`, `minor = (payload >> 8) & 255`, and
`patch = payload & 255`. The largest supported version, 63.255.255, encodes as
`0x3fffff45` (1073741637).

The CIP registry entry for Dingo must link this specification to authorize
nonzero payloads under the registry's rules.
