# Byron preprod chunks

Chunks 0 and 1 of the preprod ImmutableDB in cardano-node's on-disk layout
(21600 slots per chunk, a leading relative slot for the epoch boundary block):
the genesis epoch boundary block and the Byron main blocks that follow.

What is verified, by `TestByronFixtureIsPreprodChain` in `byron_test.go`:

- The first block, the epoch 0 boundary block, names the preprod Byron genesis
  hash from `config/cardano/preprod/config.json` as its predecessor.
- Every later block names the header hash of the block before it, so the files
  hold one unbroken stretch of the preprod chain from genesis.
- Each secondary-index header hash equals the hash recomputed from the block
  bytes.

`TestStoreReproducesCardanoNodeByronChunks` further pins that writing these
blocks through the store reproduces the files byte for byte.

The files are binary and not regenerated by any test. The record of which
cardano-node or Mithril download they were first taken from was not kept; the
checks above are what establish them.
